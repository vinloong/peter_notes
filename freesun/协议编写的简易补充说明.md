## 协议编写的简易补充说明

协议主要分为两种，一种是需要我们下发采集命令，等待设备回复，另外一种是设备主动上报：

1. 下发采集指令
   需要在start方法执行`ssend`同步发送。最终数据通过方法`ctx:done`返回。
   
   ```lua
   ok, resp = ctx:ssend(buff, 15000)
    local result = '{}'
    if ok then
        result = unmarshall(resp, moduleNo)
    else
        log.debug('blm_tempHumi_1104 SSend error!')
    end
    ctx:done(result)
   ```
   
   另外，一般定义`unmarshall`方法实现码流解析，其中定义`IsValid`方法实现码流校验。
   
2. 设备主动上报
   需要在`OnData`方法中执行,最终数据通过 `ctx:notify`返回。
   
   ```lua
   onData = function(hex)
   
       local ErrorCode = IsValid(hex.payload)
       log.debug('xxxx hex.payload=%s',hex.payload)
       ... 
       -- 如果数据中没有时间，取当前时间作为数据时间
       local timeData = os.date("%Y-%m-%dT%H:%M:%S") 
       local out = {
           data = {
               xAngle = xAngle,
               yAngle = yAngle,
               temperature = temperature
           },
           device = device.id,
           type = 2,
           time = timeData.."+08:00"
       }
   
       --异步发送数据
       local resultData = json.encode(out)
       log.debug('qj_ax_sz result_out= %s',resultData)
       ctx:notify(resultData)
   ```
   
   

文档开头写参考协议文档名称，以及作者（`AICracker`）
协议中使用log进行日志记录，每个协议有个日志名称标签，一般用协议名称拼音或首字母。
添加适当的注释。
如果有样例码流，建议用注释写在脚本中。

如果用到其他需要的参数（比如设备模块号、计算公式参数），可以定义在设备属性上，这里通过 `device.props`获取(props下的属性是自定义的)。

```lua
local modeleId = device.props.model
```



如果要处理包含子设备的设备（如采集仪、网关），需要从`device.dnlinks`获取子设备，如下：

```lua

function getDeviceInfo(moduleid)
    --log.debug('xxx 查找设备=%s',moduleid)
    if device.dnlinks ~= nil then
        for _, dnlink in pairs(device.dnlinks) do
            for _, subdevice in pairs(dnlink.devices) do
                if tostring(subdevice.uplink.props.module) == tostring(moduleid) then
                    log.debug('xxx 匹配到设备=%s', subdevice.name)
                    return subdevice
                end
            end
        end
        return nil -- 没有找到匹配的传感器
    else
        log.debug('xxx has no subdevices.')
        return nil -- 没有子设备
    end
end
```
